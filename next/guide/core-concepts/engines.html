Engines ​

Once you have defined your data with Models, you'll want to store it somewhere. In order to configure where the data ends up, you'll use Engines.

You can set the default engine calling the setEngine method:

ts
setEngine(new InMemoryEngine());

If you're interested in learning how the library behaves, you can start using the InMemoryEngine and inspect the documents property, which is just a plain JavaScript object with the serialized RDF graph:

ts
const engine = new InMemoryEngine();

setEngine(engine);

await User.create({ name: 'John Doe' });

// Inspect the database
console.log(engine.documents);

These are the engines that come built-in:

  • SolidEngine: Stores data in a Solid POD. You can learn how to configure it in the Configuration section.
  • IndexedDBEngine: Stores data in IndexedDB.
  • InMemoryEngine: Stores data in memory.

Regardless of the engine you use, data is always stored as RDF documents. This means that you can move data from one engine to another without any transformation, which is what makes local-first applications possible.

Model engines ​

In addition to the default engine, you can also configure the engine for specific models using the static setEngine method:

ts
User.setEngine(new IndexedDBEngine());

If you need to use a different engine temporarily, you can also use the runWithEngine helper. However, keep in mind that this relies on async context tracking, so you'll need to configure an AsyncContextManager with setAsyncContextManager first (for example, using Node's AsyncLocalStorage):

ts
import { AsyncLocalStorage } from 'node:async_hooks';

import type { Engine } from 'soukai-bis';

const storage = new AsyncLocalStorage<Engine>();

setAsyncContextManager({
    runWithValue: (engine, operation) => storage.run(engine, operation),
    getValue: () => storage.getStore(),
});

await runWithEngine(new InMemoryEngine(), () => User.create({ name: 'John Doe' }));

Storing data ​

Once you've defined your Models and configured an Engine, you have a couple of options to store your data.

First, you can create a new Model instance and call the save method:

ts
const user = new User({
    name: 'John',
    surname: 'Doe',
    birthDate: new Date(),
});

await user.save();

You can also achieve the same result in a single line using the static create method (or createAt, if you want to indicate the container):

ts
await User.create({
    name: 'John',
    surname: 'Doe',
    birthDate: new Date(),
});

For persisting model updates, you also have a couple of options.

You can update the Model attributes as usual, and call the save method to persist changes:

ts
user.name = 'Jane';
// or...
user.setAttribute('name', 'Jane');

await user.save();

Or you can use the update single liner to both update the model and persist the changes:

ts
await user.update({ name: 'Jane' });

⚠️ Beware of concurrent updates

Saving a model that was updated remotely after your last synchronization may not work as expected because the internal state may differ. Also, depending on the engine you're using, calling the save method multiple times on the same model may fail due to race conditions. Make sure to debounce the calls so that you don't have multiple operations going on concurrently.

Fetching data ​

Once you have written some data in your storage, you can retrieve single models by url using the find method (or findOrFail, if you want to throw an error when the model doesn't exist):

ts
const user = await User.find('https://example.org/users/john#it');

console.log('User with url "https://example.org/users/john#it"', user);

You can also get multiple instances with the all method:

ts
const users = await User.all();

console.log('All users', users);

By default, this will read models from the default container, but you can read them from other containers using the from option. It's also possible to read models from nested containers using the deep or depth options:

ts
const users = await User.all({ from: 'https://example.org/users/', depth: 2 });

console.log('Users in "https://example.org/users/" (and up to two levels of nested containers)', users);

If any of the documents fails to be parsed, the method will throw an error. But you can use the onDocumentError option to handle these errors and continue reading the other documents.

Deleting data ​

Finally, when you need to delete data, you can use the delete method:

ts
await user.delete();

If the model is the only resource in its document, the document will be deleted. Otherwise, only the resources related with the model will be removed from the document.
