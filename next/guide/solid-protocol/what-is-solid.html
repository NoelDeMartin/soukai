What is Solid? ​

The Solid Protocol is a standard for decentralized storage that uses Linked Data (RDF). It was created by Tim Berners-Lee, the inventor of the Web, and it fulfills his original vision for how the Web should work. If you're keen to learn more about its history, check out Tim's book This Is for Everyone (or the audiobook narrated by Stephen Fry!).

The way it works is that data is stored in Solid PODs (Personal Online Datastores); which are servers that users control or delegate to someone else. Similar to email, you can choose where you want data to be stored, but Solid has a much greater scope since it's intended for all sorts of applications. In this sense, Solid Applications are decentralized because they can connect to any backend that supports the protocol. It could be a managed service that you rent, or a self-hosted computer in your basement.

Soukai and Solid ​

Working with Solid directly can be challenging. You need to parse and serialize RDF, keep track of which triples have changed in order to send PATCH requests, discover where data lives in a POD, and so on.

Soukai simplifies all of this, and you can work with plain JavaScript objects using a familiar Active Record API:

ts
const url = 'https://alice.example.org/movies/spirited-away#it';
const movie = await Movie.findOrFail(url);

await movie.update({ title: 'Spirited Away (千と千尋の神隠し)' });

Under the hood, the library will read the RDF document, update the model attributes, and send a SPARQL PATCH request to the POD with only the triples that have changed.

All models are read from and stored in a Solid POD using the SolidEngine, which only needs an authenticated fetch (you can learn how to configure it in the Configuration section). And because every engine stores the same RDF, you can also store your models locally (for example, using the IndexedDBEngine) and synchronize them with a POD to build local-first applications.

There are also some built-in models to work with common Solid resources, such as Person (for user profiles), Container, TypeIndex, and TypeRegistration. You can learn more about them in the Interoperability section.
